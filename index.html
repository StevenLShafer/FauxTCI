Pump limits and timing

Declared latency is the request's timing.latency; actual is what the pump really takes (differ them to teach the cost); the interval is how long each rate is held (STANPUMP: 10 s).

The page will POST to <URL>/tci/v1/drugs/<drug>/rate. The server must allow this page's origin (CORS): stanpumpR::run_tci_api() sends no CORS headers, so put a proxy in front of it that adds them, or add a Plumber filter in a development session. Never on a production ingress.

Start locks these for the case; the clock can still be changed. Stop sets the target to 0 and halts the clock; the record stays until the next Start.

    Drug given outside the pump: the record gets a bolus event and the controller gives nothing until the effect site is back at target.

    A paused pump reports pump.state: paused and rate 0; the server still plans, projecting the latency at zero, and the pump decides not to run it.

    The next response is lost in transit: the pump runs its segment to holdUntil, then the fallback rate, then it would stop and alarm (section 7, rule 4).

    The controller is told one concentration while the syringe holds another: the true and predicted curves diverge, and the controller can only be as right as its record.

      About FauxTCI

      FauxTCI is a simulated target-controlled infusion (TCI) syringe pump and its controller, running entirely in this page: no server, no framework, no build step. Set the pump's limits, pick propofol or remifentanil, enter a target, and watch the pump run: the loading infusion, the pause until the effect site peaks, the hand-off to a slowly falling maintenance rate, and what happens on a hand bolus, a pause, a lost response or a wrong syringe. The right-hand panel shows every request the pump sends and every response it receives, because the point of FauxTCI is to show how a pump talks to the controller.

      What the controller is. The controller in this page is a JavaScript reimplementation of the stanpumpR TCI API (docs/tci-api.md): the same request body in, the same response body out, the same algorithm (Shafer and Gregg 1992, as in tciRate()) and the same two drug models (Eleveld 2018 for propofol; Eleveld 2017 and Kim 2017 for remifentanil). It is validated against fixtures generated by the R package at stanpumpR commit 740b5055f12c9616cac4fec869ab2b6d1b3b777a: the drug models to 1e-10 relative, the API responses to 1e-8 relative, and six 30-minute closed-loop traces to 1e-6 relative in the true effect-site concentration. It is not the R service. The Controller switch in the setup lets the page call a real stanpumpR::run_tci_api() server over HTTP instead, when one is reachable.

      Clinical disclaimer. FauxTCI is a teaching simulation. It is not a medical device, it has not been evaluated by any regulator, and nothing in it is to be used for patient care, for programming a real pump, or for any clinical decision.
